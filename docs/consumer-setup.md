# 設計プロジェクトへの導入（consumer setup）

rtl-harness は各 FPGA プロジェクトに **git submodule** として取り込みます。プロジェクト側に残るのは
`harness.toml`（唯一の手書き設定）と、生成される入口ファイルだけです。

## 前提

- Windows: MSYS2（ucrt64）、`uv`、`git`、`gh`（Issue 連携を使う場合）
- Linux: `verilator` 5.048、C++ ツールチェーン、`uv`
- ハーネス自身の環境構築は `scripts/setup_toolchain.ps1` / `.sh` が行います

## 手順

```powershell
# 1. submodule として取り込む（タグで固定）
git submodule add https://github.com/MameMame777/rtl-harness.git harness
git -C harness checkout v0.1.0
git commit -m "chore: add rtl-harness v0.1.0"

# 2. ツールチェーン（2 つの venv、Verible、gitleaks、VPI ライブラリ）
.\harness\scripts\setup_toolchain.ps1

# 3. プロジェクト設定
Copy-Item harness\templates\harness.toml .\harness.toml    # sources / domains / tests を編集

# 4. チケット機能と入口ファイル
uv run --project harness rtl-harness provision              # 無いものだけ追加（tickets/、Issue テンプレ、ラベル）
uv run --project harness rtl-harness sync                   # CLAUDE.md / copilot-instructions / .mcp.json / .vscode/mcp.json（P3）

# 5. 動作確認
uv run --project harness rtl-harness doctor
uv run --project harness rtl-harness lint
uv run --project harness rtl-harness sim <block>
```

`sync` が生成するファイルには `generated by rtl-harness sync ...` のヘッダが入ります。手で編集せず、
`harness.toml` を変えて `sync` を再実行してください。CI では `sync --check` が差分を検出します。

## プロジェクト側の構成

```text
<project>/
├─ harness/            submodule（rtl-harness）
├─ harness.toml        プロジェクト設定
├─ rtl/                RTL（[design].sources）
├─ tb/                 test_<block>.py（[sim].tests）。harness_tb.runner_support.build_and_test を呼ぶ
├─ tickets/            provision が追加。rtl-harness ticket new で起票
├─ .harness/           build / logs / last（gitignore に追加する）
├─ CLAUDE.md, .github/copilot-instructions.md, .mcp.json, .vscode/mcp.json   sync が生成
└─ .pre-commit-config.yaml, .github/workflows/harness.yml                    sync が生成
```

`.gitignore` に `.harness/` を追加してください。

## テストの書き方

`docs/verification.md` と `harness/tb/README.md` を参照。最小の形:

```python
from pathlib import Path
import cocotb
from harness_tb.lib.clkreset import bringup
from harness_tb.lib.scoreboard import check_eq

@cocotb.test(timeout_time=1, timeout_unit="ms")
async def counts(dut):
    clk, _ = await bringup(dut)
    ...

def test_my_block():
    from harness_tb.runner_support import build_and_test
    build_and_test(block="my_block", sources=["rtl/my_block.sv"], toplevel="my_block",
                   test_dir=Path(__file__).parent)
```

## ハーネスの更新

submodule のタグを進めるだけです。強制ルールは警告（マイナー版）→ エラー（メジャー版）の 2 段階で
入るので、マイナー版の更新で CI が落ちることはありません。

```powershell
git -C harness fetch --tags
git -C harness checkout v0.2.0
uv run --project harness rtl-harness sync
git commit -am "chore: rtl-harness v0.2.0"
```
